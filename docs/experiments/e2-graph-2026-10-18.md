# E2 experiment: entity graph vs dense fusion — 2026-10-18

- Protocol: `mem eval --bootstrap --n 200 --seed 7` (187 queries;
  phrase pool saturated at 37), budget 600, own memory home sandbox
  (/tmp/mh4 copy; repo home untouched), corpus after full
  distill→daily→consolidate→graph rebuild (16 distilled objects,
  9 daily cards, 1854 typed bitemporal edges).
- Decision rule: `mem/graph.py::scorecard`, wired into every
  `eval` run; verdict lands in `metadata/eval_report.json` as
  `graph_decision`. Keep only if multi-hop (multihop+conceptual avg)
  beats the best non-graph mode, single-hop exact holds within
  ±0.05, and tok/q stays within 1.25x of that reference.

| mode      | MRR    | P@1    | tok/q  | multihop | exact | phrase | conceptual |
|-----------|--------|--------|--------|----------|-------|--------|------------|
| baseline  | 0.7326 | 0.7326 | 332.9  | 0.000    | 1.000 | 1.000  | 1.000      |
| distilled | 0.0535 | 0.0535 | 57.0   | 0.000    | 0.080 | 0.000  | 0.120      |
| fused     | 0.8070 | 0.7701 | 566.5  | 0.278    | 1.000 | 1.000  | 1.000      |
| graph     | 0.7934 | 0.7487 | 560.4  | 0.227    | 1.000 | 1.000  | 1.000      |

## Finding

Multihop recall on this corpus is already delivered by the dense
vector side of fusion (0.278): documents are small and share entity
tokens, so cosine reaches across one bridge entity without graph
traversal. Explicit 2-hop expansion adds candidate noise
(0.227 < 0.278 on multihop) and no gain elsewhere while keeping the
~560 tok/q cost. Single-hop never degraded (tiered lexical backbone,
see FAILURES F-08) — the predicted Mem0 single-hop penalty did not
materialize; the loss is multihop dilution instead.

## Decision

**drop-to-routed** (recorded by scorecard, verified by hand above):
the graph stays rebuildable and available via `mem recall --mode
graph` and `mem graph --build`, but `fused` remains the default read
path. `graph.scorecard` re-runs on every `eval`; if a future corpus
(denser cross-document entity chains, larger docs where token
overlap no longer bridges hops) shows graph multihop > fused
multihop within token tolerance, the verdict flips to `keep-graph`
automatically and this note gets superseded by a follow-up entry.

Bounded rerun: `cd tools/mem && MEM_HOME=<sandbox> ./.venv/bin/python
-m mem eval` — the sha of the queryset and the protocol stamp in
`metadata/eval_stamp.json` make rows comparable.

## Correction note — 2026-10-18 (G-G3): verdict downgraded to
## inconclusive under bootstrap CIs

The drop-to-routed decision above was declared on point estimates
(graph multihop 0.227 vs fused 0.278, n=50) — a gap of ~0.05 on
fifty queries. Adding bootstrap confidence intervals (G-G3) shows
the two multihop CIs overlap: fused [0.1867, 0.3817] vs graph
[0.1537, 0.31] (seed 42, same corpus, `mem eval --seed 42`). The
original verdict was made on sampling noise; it stands as the
recorded historical decision, but it is no longer defensible as a
measurement.

`graph.scorecard` now enforces the rule going forward: when the
graph and reference multihop CIs overlap, the verdict is
**inconclusive** — no drop, no keep. Rerun with CI:

    MEM_HOME=<sandbox> ./.venv/bin/python -m mem eval --seed 42
    # -> modes.graph.per_type.multihop.ci95 vs fused's are compared;
    #    overlapping intervals => "inconclusive"

Seed rotation (`mem eval --rotations 3`) grows the measurement
across disjoint-ish querysets (3 seeds x 187 = 561 queries pooled),
reports per-seed variance (fused ±0.0124 across seeds) and pooled
CIs; on this corpus the multihop comparison remains
inconclusive. The default read path stays `fused` for token-cost
reasons (graph ~554 tok/q vs fused ~577 tok/q is within tolerance;
single-hop exact shows no graph advantage), not because the graph
loss was measured. A `keep-graph` verdict now requires a
statistically separated multihop win.
